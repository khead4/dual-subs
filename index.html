4. Processing Flow

Receive the source, add two subtitle languages, then stream or download the video

This page is designed around the exact product workflow: accept a video upload or link, build the native timed transcript internally, translate it into two user-selected subtitle languages, and apply both subtitle tracks to the video with a fixed buffer so legibility stays intact.

This simulates the job orchestration your server will execute once real transcription, translation, and video-render services are connected.

System Design

How this becomes a real product

01

Hidden transcript first

Yes, the foundation is a transcript broken into cues with start and end times. Every translation stays attached to the same cue IDs so the two added subtitle tracks remain synchronized with the source.

02

Two added subtitle languages

Each cue gets translated twice using your translation model of choice. The system stores both outputs side by side instead of overwriting a single subtitle lane.

03

Render safely

Layout rules decide which lane sits above the other, how much padding is reserved, and when line breaks or font scaling are needed to preserve legibility.

04

Deliver flexibly

The web player can stream the subtitle lanes as overlays, while the backend can also prepare a downloadable video result with the two added subtitle languages attached.
